# Ordivant Work

Work 用來整理專案、任務、Agent 執行、訊息、成果證據與獨立審核。Task 是業務工作；Run/Execution 是一次實際執行。執行完成不會自動把 Task 標成完成，必須由有權限且非提交者的審核者接受成果。

三個模組的主要頁面、所選專案或 Space，以及 Work 的規劃、自動化與工具子分頁會保存在網址中；重新整理後會回到原本的位置，也可以將網址加入書籤。已開啟的任務、Knowledge 文件與 Code 合併請求可透過網址還原。登入後仍會重新檢查存取權；已刪除或不再能存取的專案、Space 或儲存庫會改選可存取的項目。尚未送出的表單內容不會因此自動儲存。

## 使用側邊導覽 {#sidebar-navigation}

Work 導覽分為「專案工作」（專案總覽、任務、規劃工作區、協作收件匣）、「Agent 與執行」（Agent 名錄、Run 執行、自動化）及「管理與設定」（工具與沙箱、操作稽核；管理員另可使用模型連線）。選取頁面會保留目前專案。

三個模組的側邊欄底部只保留帳號列；頭像旁的狀態點表示服務連線狀態，移到狀態點上可查看說明。點擊帳號列可開啟浮動選單，使用通知、搜尋、設定、語言切換及登出，不會擠壓導覽區。點擊選單外或按 Escape 可關閉。小螢幕使用「前往頁面」分類選單。

## 清理 Agent 名錄 {#retiring-agents}

專案管理者或管理員可在「Agent 名錄」使用「永久刪除 Agent」或「封存 Agent」，確認後才會執行。同一 Agent 若屬於多個專案，操作者必須有全部相關專案的權限。

- **永久刪除**：只適用於未使用、沒有任務、執行、協作或設定引用的 Agent。會移除 Agent、專用身分、憑證、專案成員資格及模型／執行設定，無法復原；稽核紀錄仍保留。
- **封存**：保留 Agent 名稱、既有任務、成果、執行與稽核紀錄，同時撤銷憑證並從預設名錄、可指派對象與人員統計隱藏。勾選「顯示已封存的 Agent」即可查看；已封存的 Agent 無法重新啟用、編輯或接收新工作。
- **仍有工作**：先停止 Run，將未結束任務交接、改派、完成或取消，並停用或改派仍使用該 Agent 的自動規則與排程。即使任務尚未開始或 Agent 只擔任指定審核者，也須先處理。

上述操作不需要 LLM。停用只暫停 Agent 的使用，不會將它從名錄隱藏；停用後，同一位置會顯示「重新啟用」，管理者可恢復 Agent 的可用狀態與指派資格，原有設定及歷史紀錄會保留。執行中的 Agent 必須先結束執行才能變更狀態。不再使用且需要保留歷史時，請改用封存；封存後不能重新啟用。

## 使用預設 Agent 範本 {#built-in-agent-templates}

在專案的「Agent 名錄 → 新增 Agent」，先選擇「Agent 範本版本」。系統提供六種內建職務：

| 範本 | 用途 |
|---|---|
| PM · 專案經理 | 目標與範圍、任務分解、相依性、風險與交接 |
| PG · 程式開發 | 功能實作、問題修正、程式碼與測試證據 |
| SA · 系統分析 | 業務流程、需求、權限與可追溯驗收條件 |
| SD · 系統設計 | 架構、API、資料模型、取捨與遷移計畫 |
| QA · 品質驗證 | 測試規劃、實際驗證、可重現缺陷與覆蓋缺口 |
| Reviewer · 獨立審查 | 核對成果及證據，提出接受或退回理由 |

套用後會帶入建議名稱、平台角色、能力標籤與工作指令，並預設「由平台執行」、繼承組織模型設定。可在建立前修改；手動輸入的名稱會保留。

「執行方式」決定由誰啟動 Agent。一般使用者選擇「由平台執行（建議）」，由平台使用已設定的模型執行任務並追蹤進度；管理員須先啟用執行服務。若已有自行開發或串接的 Agent 程式，選擇「由外部程式執行」，讓該程式透過 API 或 MCP 認領任務、回報進度與成果；平台不會啟動外部程式，模型及連線由該程式設定。執行方式建立後無法變更。

Reviewer 使用審核者角色，其餘職務使用執行者角色；職務名稱不會額外授予管理員權限。範本套用到目前專案，工具及 Sandbox 由管理者另行選擇。獨立審查仍須符合伺服器端授權與執行者分離規則。

「自動化 → Agent 範本版本」可查看內建範本、套用版本或新增自訂版本。內建文字支援三種介面語言，已輸入的草稿與自訂範本保留原文。範本按組織保存為不可變版本，既有 Agent 及 Run 保留已套用的設定。REST API 與 MCP 的 `list_agent_templates` 也能取得這些版本。

## 建立專案與任務 {#create-projects-and-tasks}

1. 由 Identity 管理員在 Work 建立 Project，並把成員授權到這個 Project。成員只會看到自己獲授權的範圍。
2. 在 Project 的「任務」建立 Task，填寫目標、描述、輸入資料、執行範圍、限制、驗收條件和優先順序。
3. 在「負責者」選擇管理員已授權此 Project 的真人同事或 Agent，也可先留白讓合資格成員認領；在「指定審核者」選擇另一位獲授權的真人或 Agent。需要先完成的 Task 可加為 dependency。系統拒絕循環依賴；前置任務要完成獨立審核後，後續任務才可開始。
4. 儲存後在任務清單搜尋或依狀態查看工作。修改任務規格不會取代已保存的執行與審核歷程。

Work 專案建立後，系統會詢問是否一起建立同名、同描述的 Knowledge 空間與 Code 專案。可勾選其中一項、兩項，或略過。Knowledge 沿用 Work 代碼；Code 代碼轉為小寫並將底線改為連字號。各產品仍獨立授權；服務未啟動、代碼衝突或權限不足會個別顯示，已成功項目不會重複建立，Work 專案仍可使用。此步驟只建立 Code 專案，儲存庫可稍後在 Code 建立。

真人可指派對象必須已受邀、啟用，並具有 Work 角色及此 Project scope；即使受邀者尚未登入 Work，管理者仍可先將工作交給他。角色與範圍由 Identity 管理員設定，詳見[團隊設定](team-setup.md)。

## 執行並提交證據 {#execute-and-submit-evidence}

真人工作不需要 LLM 或 Agent。具有此 Project scope 的 Worker、Manager 或 Admin 可認領未指派給別人的待執行任務；若任務已指派給自己，也可認領。直接按「認領任務」，不必選 Agent。不能代替另一位同事認領。真人執行沒有 Agent 租約，工作從任務執行紀錄恢復，所以重新載入後可繼續處理。

處理中可使用「回報執行進度」留下進展與證據；需要等待外部資料時選擇「標記任務受阻」。受阻或成果被退回時，原負責者仍保留。若要交給其他人，選擇「交接並釋出」並寫下交接內容：目前執行會結束、交接會留在歷程，真人負責者清除，任務回到待執行，其他合資格同事即可認領。Manager/Admin 也能在尚未開始執行時改派負責者。

完成後提交摘要及一項或多項成果，例如文字、Artifact URI 或檔案／測試結果引用。提交會把 Task 移入待審核並保留執行、證據與交接歷程。請說明成果如何符合驗收條件；提交不等於任務已接受。另一位有權限且不是提交者的人選擇接受或退回；提交者不能審查自己的成果。

若派發給 Agent，管理員須先啟用 Agent 執行服務；Pi 自動 Run 才需要模型設定。Agent 執行仍使用自己的租約與 fencing token，與真人工作分開。派發操作詳見[Run 與自動化](../execution-usage.md)。

## 協作與引用 {#collaboration-and-citations}

在 Task 脈絡使用訊息向其他成員或 Agent 提問、回覆、交接工作或記錄決議。Project 的 Manager／Admin，或父任務的真人、Agent 負責人，可選擇「委派子任務」把工作交給具備此 Project 執行權的同事或 Agent；委派不會自動授予受託人其他 Project 的存取權。

若工作依賴 Knowledge 文件，將該文件的**特定版本引用 URI** 放入 Task 輸入或提交證據，並保留版本號。引用只是來源紀錄，不會替讀者授權 Knowledge Space；需要閱讀原文的成員必須另外獲授權。Knowledge 引用格式與操作見[Knowledge 指南](knowledge.md)。

Work 也能讀取已設定的既有 GitHub、GitLab 或 Gitea PR/check 狀態。這是專案範圍內的讀取與證據檢視；它不會合併 PR，也不會代替獨立審核。Code 中由 Gitea 管理的 repository 與 PR 操作見[Code 指南](code.md)。

## Run 控制 {#run-controls}

在「Run 執行」查看每次執行的狀態、事件與用量。管理員或專案管理者可暫停、繼續、停止或重試。暫停會在下一個工具操作前生效，並保留任務；停止後，本次執行不能再更新任務。重試會建立新的 Run。已完成的外部操作不會因停止而撤銷，重試前請先核對結果。

控制台的 Run 狀態、等待與停止語意、沙箱和工具設定詳見[執行使用指南](../execution-usage.md)。工具外部副作用不會因重試而自動重播；不確定的操作結果應先到上游服務核對。

## 權限概覽 {#permissions-overview}

- **Manager**：管理已授權 Project 的任務與執行安排。
- **Worker**：認領未指派或指派給自己的工作，提交成果並可交接釋出。
- **Reviewer**：審查提交的成果；不能批准自己的提交。Manager 和 Admin 也可在獲授權範圍審查。

組織管理員負責建立 Project、邀請成員及分配產品角色。Work 存取以 Project scope 與 manager、worker、reviewer 身分為準；沒有獨立的 Work Reader role。人類登入工作階段不會變成 Agent/runtime 憑證。

## 規劃工作區 {#planning-workspace}

在 Work 側欄選擇「規劃工作區」，再選擇 Project。用「看板」查看任務生命週期，用「Backlog 排序」調整專案工作次序；搜尋與篩選可依狀態、任務類型、Sprint、里程碑、負責者及逾期情況縮小清單。設定篩選後輸入名稱並選擇「儲存查詢」，可在之後載入自己的查詢。

管理者在任務列選擇「規劃」，可編輯工作類型（task、story、bug 或 epic）、Epic 關聯、開始日、到期日、Sprint、里程碑、預估點數、規劃階段與專案自訂欄位。Backlog 的上下排序只改排序，不會改變狀態。階段必須對應任務目前狀態；看板上的規劃狀態控制只允許 backlog、ready、cancelled，執行中、受阻、審查及完成仍由既有執行與審查流程控制。

在「規劃設定」由有管理權限的成員建立 Sprint、里程碑、自訂欄位、規劃階段、事件規則及任務提報表單。每個 Project 同時只能有一個 active Sprint；關閉 Sprint 不會完成其中任務。自訂欄位一旦被任務使用，欄位 key 與型別不可更改。事件規則在任務建立或更新時同步套用標籤、指派負責者或把 backlog 任務送入 ready；規則不會派發 Agent Run、認領任務或完成審查。

「任務提報」讓已登入的 Project 成員選擇啟用中的表單，填寫標題、描述和表單指定欄位。送出後會建立 backlog 任務，交由有權限的成員整理、排序及指派；此表單不是匿名公開入口。

在任務列選擇「工時」可記錄工作分鐘、開始時間和摘要，紀錄歸屬目前登入者。Manager 可在「工時與報表」查看工時、週期及各成員容量，也可匯入或匯出 CSV。管理者須為每位 Project 參與者（真人或 Agent）明確設定每週容量分鐘數；未設定時使用率保持空白，不會由系統推估。週期從任務首次執行開始，到獨立審查接受為止，包含重做及等待審查時間；它不是實際投入工時。CSV 匯入會先整批驗證，無效資料不會部分寫入；匯出會避免試算表公式注入。報表只反映已記錄及觀察資料，不預測未來工時或費用，也不會把 Agent 自報成本變成已驗證費用。

## 附件、追蹤與協作中心 {#resource-collaboration-center}

在 Task 詳情的「附件與協作通知」面板上傳附件、下載仍有權限存取的附件、追蹤更新，或寫留言並提及有權限的同事與 Agent。單一附件上限為 10 MiB，清單會顯示檔名、大小與 SHA-256 摘要。留言和附件通知會顯示在共用協作中心；追蹤不會寄送電子郵件。

畫面右上方的鈴鐺可開啟「通知中心」，查看並標示通知為已讀；搜尋按鈕可跨目前有權限使用的 Work、Knowledge 和 Code 模組查找內容。結果只包含目前帳號可存取的資源；服務暫時不可用時會分別顯示錯誤，不會把缺少的結果當成搜尋成功。搜尋不需要 LLM。開啟通知連結時，平台會再次檢查資源存取權；權限撤銷後不會顯示原本的內容。

## 選擇專案與管理設定 {#project-settings}

側欄上方的「目前專案」會顯示所選專案。先選擇專案，再使用下方的任務、規劃工作區、Agent、執行、自動化與專案管理功能。頁面頂端的路徑也會顯示專案代碼、名稱與目前功能，方便確認操作範圍；網址會保留專案與頁面選擇，重新整理後可繼續操作。

開啟「專案管理 → 專案設定」：

- **基本資料**：專案管理者可修改名稱、說明與追蹤預算；專案代碼建立後不變更，預算不是模型費用的強制上限。其他成員可查看。若有人先儲存修改，畫面會提示衝突，請重新載入後再編輯。
- **成員與權限**：系統管理員可授予或移除此 Work 專案的存取權，不影響其他專案或產品。變更會撤銷該成員目前的登入，請成員重新登入。尚無 Work 角色的成員會以工作者加入；已有角色會保留。SCIM 管理的權限需至佈建群組調整；手動修改 SSO 權限會停止該帳號的企業群組權限同步。
- **相關工作區**：管理員可建立對應的 Knowledge 空間與 Code 專案。三個模組分別管理資源與授權；同名不代表已連結或自動共用權限。

目前 Work 的存取範圍依專案區分，角色以產品為單位：同一位成員在獲授權的 Work 專案使用相同角色，尚不支援各專案獨立角色或 Work 唯讀角色。若要修改角色，請開啟「組織管理 → 使用者與邀請」；Agent 則從該專案的「Agent 名錄」管理。

個人密碼、登入工作階段及個人 API 權杖位於左下帳號選單的「帳號設定」。企業 SSO、組織成員及模型連線位於「組織管理」，不屬於個別專案設定。以上專案管理與真人協作皆不需要 LLM。
