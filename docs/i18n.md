# 語言與翻譯 {#language-and-translation}

文件站提供繁體中文、English 與简体中文。切換語言時會開啟同一篇文章的對應版本；所選文件語言會保留在網址中，因此重新整理或加入書籤後仍會維持該語言。公開範圍由 `docs/.vitepress/public-pages.json` 明確列出使用者指南及其三語版本；清單外的 Markdown 不會進入網站、搜尋索引或 sitemap。

應用介面提供繁體中文、English 與簡體中文。選擇後會保存於同源瀏覽器儲存空間 `localStorage` 的 `ordivant.locale`，並同步到其他分頁。變更介面語言不會重載頁面或清除表單。首次使用且尚未選擇時，應用會參考 `navigator.languages`：繁體中文地區代碼 `zh-TW`、`zh-HK`、`zh-MO` 使用繁體中文；其他中文地區使用簡體中文；英文使用 English；不支援的語言使用繁體中文。

語言切換只會改變應用介面、文件站導覽、搜尋介面與文件文字。Ordivant 不會自動翻譯使用者建立的 Work 專案與任務、Agent 指示、訊息、Knowledge 文件、Code 內容或模型回覆。這些內容會依照提交者輸入的語言保存，使用者與 Agent 必須自行選擇合適的語言。

## 開發應用介面翻譯 {#developing-application-translations}

應用翻譯位於 `frontend/src/i18n`。語言代碼為 `zh-TW`、`zh-CN` 與 `en`；繁體中文文案是 source key，英文對照放在 `catalogs/*.en.ts`，簡體中文對照放在 `catalogs/*.zh-CN.json`。source key 和 `useI18n()` 的 `t()` 僅供介面文案使用，不要拿來翻譯使用者建立的內容。

元件使用 `useI18n()` 訂閱目前語言並取得 `t()`。需要將錯誤或狀態訊息保存到 React state 時，使用 `localized(source, values)` 保存原始文案與插值值；顯示時再交給 `t()`，語言變更後就能呈現新語言，且不會丟失訊息內容。表單呼叫 `useLocalizedForm(form)`；語言變更只會重新驗證已有錯誤的欄位，不會送出表單、清除草稿或重設欄位值。

```sh
npm --prefix frontend run i18n:check
```

英文與簡體中文翻譯均由貢獻者直接撰寫及校訂，不使用自動繁簡轉換產生翻譯。新增或修改繁體中文 source key 時，同步更新對應模組的英文及簡體中文條目，依語意採用自然的當地用詞，例如「儲存庫」對應「代码仓库」、「標準作業程序」對應「标准操作流程」。API 識別字與 `{{name}}` 等插值保持不變。

`i18n:check` 只讀取翻譯檔，驗證是否有缺漏、空白、非字串、過時 key、跨模組衝突或插值不符，並以實際翻譯檔檢查語言切換。檢查不會產生或覆寫翻譯；語意與用詞仍須人工審閱。

新增或修改介面翻譯後，先執行目錄檢查與四種前端建置，再於一般本機開發環境檢查變更的畫面：

```sh
npm --prefix frontend run i18n:check
npm --prefix frontend run build:suite
npm --prefix frontend run build:work
npm --prefix frontend run build:knowledge
npm --prefix frontend run build:code
```

修改公開文件後，建置三語文件並檢查公開連結與轉址頁：

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv run --project backend --no-sync python scripts/check_docs.py
node scripts/build_docs_redirects.mjs
```

需要瀏覽器檢查時，先執行 `npm --prefix docs run preview`，再開啟本機預覽。檢查修改文章的三語頁面、語言切換後的對應路徑、標題錨點、搜尋結果及手機版版面；確認只有公開清單中的文章出現在網站。

## 參與翻譯 {#contributing-translations}

繁體中文根目錄是目前的文件來源。其他語言使用相同的相對路徑，例如 `docs/guide/work.md` 對應 `docs/en/guide/work.md` 與 `docs/zh-CN/guide/work.md`。只有 `docs/.vitepress/public-pages.json` 列出的文章會公開；新增公開文章時，在清單加入不含語系前綴的相對路徑，例如 `guide/work.md`，並建立三語對應檔案。清單外的文件仍留在公開原始碼 repo，但不會進入網站、搜尋或 sitemap；這是發布範圍設定，不是存取控制。

- 以繁體中文原文為準，保持功能、限制、數字與安全說明一致。
- 不翻譯命令、API 路徑、環境變數、程式碼、JSON 範例、產品名稱與穩定的技術識別字。
- 保留同一篇文章的相對連結、標題 anchor、圖片路徑和程式碼區塊；新增或移動標題時同步檢查連結。
- 更新翻譯時，對照原文與另外兩種語言，避免只更新導覽或首頁而漏掉操作及契約細節。
- 執行文件建置與 `scripts/check_docs.py`，並在 PR 中列出來源頁面與已更新的語言。

翻譯尚未完成時，請明確指出缺少的語言版本，不要以另一種語言的原文充當翻譯。

## 檢查文件正文 {#checking-document-body}

`i18n:check` 會檢查 repo 內所有 Markdown 的三語標題、段落、表格與相對章節 ID，包含不公開上站的文件。公開網站建置則只收錄明確清單中的頁面；中文頁面中的未翻譯英文正文，以及英文頁面中的中文正文會使檢查失敗。命令、程式碼、API 識別字與產品名稱不在翻譯範圍內。清單內所有文章都必須有繁體中文、簡體中文與英文版本。

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/check_docs.py
```

文件預覽的瀏覽器檢查應涵蓋本次變更的三語公開頁面，確認可見正文、語言切換、搜尋、章節書籤及手機版導覽。自動檢查用來找出漏翻，翻譯者仍需對照三語內容，確認功能、限制與用詞準確。

## 文件站發布 {#documentation-publishing}

正式文件站發布於組織根網域 <https://ordivant-ai.github.io/>，由 `ordivant-ai/ordivant-ai.github.io` 的 GitHub Pages 提供。`ordivant-ai/ordivant` 保存文章原始碼；GitHub Actions 依公開清單檢查並建置文件。應用服務需另行部署。
