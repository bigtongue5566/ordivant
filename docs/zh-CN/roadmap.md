# 路线图与功能边界 {#roadmap-and-feature-boundaries}

本页说明当前可以使用的功能与尚未支持的项目，不承诺推出日期。你可以通过 [GitHub Issues](https://github.com/ordivant-ai/ordivant/issues) 提出需求、参与讨论或追踪进度；提出需求不代表一定会开发。

## v0.4.0 新增功能 {#unreleased-development}

v0.4.0 新增个人 API／MCP 令牌、PM／PG／SA／SD／QA／Reviewer 模板、Provider 模型列表，以及 Work 创建项目后选建其他产品的流程。原有看板、Sprint、附件、通知、搜索和企业集成仍可使用。见[功能导览](./features.md)、[Work 指南](./guide/work.md)和[升级说明](./release.md)。各产品维持独立授权，企业集成仍需在自己的环境验证。

## 当前可以使用 {#delivered-in-v0-1}

- **Work**：创建项目和任务，指派同事或 Agent，也可以由同事自行认领。真人可以更新进度、提交成果及交接工作，并设置任务先后关系；Agent 工作流程可以手动启动或按分钟间隔排程。
- **Knowledge**：多人实时共同编辑文档草稿，并让 Agent 通过 API／MCP 参与同一份草稿。发布后保存不可变的文档版本，也可以搜索文字、记录决策及引用确切来源。
- **Code（选用）**：连接 Gitea 进行代码协作，让同事与 Agent 参与合并请求讨论及审查；审查会标示对应的提交版本是否过期。Work 也可以查看已设置的 Git 平台上的合并请求信息。
- **登录与权限**：提供普通账号登录和 OIDC 企业单点登录；SAML、LDAP／Active Directory 可以通过选用的 Keycloak 集成接入。
- **外部工具**：管理员可以设置使用访问令牌连接的 MCP 工具。
- **运行隔离**：Docker 工作环境默认不允许网络连接，但与主机共用内核，不能视为虚拟机等级的隔离。
- **审查**：任务成果需要由另一位获授权的人员独立审查后才算完成。

普通登录、人工任务、文档共同编辑与代码协作不需要设置 LLM。只有自动运行 Agent 工作时，才需要模型服务；正式 Git 审核规则与合并仍由 Gitea 管理。共同编辑时，离线更改只暂存在当前分页，请等到显示“已保存”再离开。

## 当前限制与可能方向 {#candidates-for-future-work}

| 项目 | 当前可用 | 尚未支持 |
| --- | --- | --- |
| 工作运行 | 由一个运行服务处理工作 | 多个运行服务分散处理工作或自动扩容 |
| 操作前审批 | 可以由另一人审查已提交的成果 | 适用于所有外部工具操作的事前审批流程 |
| 模型用量与费用 | 可设置单次输出、运行轮次和时间上限，也可查看用量记录 | 尚无涵盖所有供应商的可靠费用换算或全组织硬性支出上限 |
| 通知与代码检查 | 平台内协作通知、SMTP 邀请／恢复邮件，以及上游 Git 检查和 Actions 证据 | 尚无所有协作事件的邮件／聊天通知，也不代替上游运行 CI |
| 账号管理 | OIDC 群组、账号停用、SCIM 2.0 Users／Groups 和登录政策 | 客户 IdP／目录生命周期需逐一集成验证；不支持 SCIM bulk 或按 email 自动认领现有账号 |
| 外部工具登录 | 可使用访问令牌连接 MCP 工具 | 尚无交互式工具登录或 Agent 对 Agent（A2A）连接 |
| 知识导入 | 可保存和搜索文字文档 | 尚无文档自动解析、图片文字识别、语义索引或批量来源同步 |
| 沙箱隔离 | Docker 运行环境默认禁止网络，并与主机共用内核 | 尚无虚拟机等级隔离或多个服务分散运行 |
