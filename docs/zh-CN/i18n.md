# 语言与翻译 {#language-and-translation}

文件站提供繁体中文、English 与简体中文。切换语言时会开启同一篇文章的对应版本；所选文件语言会保留在网址中，因此重新整理或加入书签后仍会维持该语言。公开范围由 `docs/.vitepress/public-pages.json` 明确列出用户指南及其三语版本；清单外的 Markdown 不会进入网站、搜索索引或 sitemap。

应用界面提供繁体中文、English 与简体中文。选择后会保存于同源浏览器存储空间 `localStorage` 的 `ordivant.locale`，并同步到其他标签页。变更界面语言不会重载页面或清除表单。首次使用且尚未选择时，应用会参考 `navigator.languages`：繁体中文地区代码 `zh-TW`、`zh-HK`、`zh-MO` 使用繁体中文；其他中文地区使用简体中文；英文使用 English；不支持的语言使用繁体中文。

语言切换只会改变应用界面、文档站导航、搜索界面与文档文字。Ordivant 不会自动翻译用户建立的 Work 项目与任务、Agent 指示、消息、Knowledge 文档、Code 内容或模型回复。这些内容会依照提交者输入的语言保存，用户与 Agent 必须自行选择合适的语言。

## 开发应用界面翻译 {#developing-application-translations}

应用翻译位于 `frontend/src/i18n`。语言代码为 `zh-TW`、`zh-CN` 和 `en`；繁体中文文案是 source key，英文对照存放在 `catalogs/*.en.ts`，简体中文对照存放在 `catalogs/*.zh-CN.json`。source key 和 `useI18n()` 的 `t()` 仅用于界面文案，不要用来翻译用户创建的内容。

组件使用 `useI18n()` 订阅当前语言并获取 `t()`。需要将错误或状态消息保存在 React state 时，使用 `localized(source, values)` 保存原始文案和插值值；显示时再交给 `t()`，语言变更后就能显示为新语言，同时保留消息内容。表单调用 `useLocalizedForm(form)`；语言变更只会重新验证已有错误的字段，不会提交表单、清除草稿或重置字段值。

```sh
npm --prefix frontend run i18n:check
```

英文和简体中文翻译均由贡献者直接编写并校订，不使用自动繁简转换生成翻译。新增或修改繁体中文 source key 时，同步更新对应模块的英文及简体中文条目，按语义使用自然的本地表达，例如用“代码仓库”表示代码存储库，用“标准操作流程”表示 SOP。API 标识符及 `{{name}}` 等插值保持不变。

`i18n:check` 只读取翻译文件，检查缺失、空白、非字符串、过时 key、跨模块冲突及插值不匹配等问题，并使用实际翻译文件验证语言切换。检查不会生成或覆盖翻译；语义和用词仍需人工审阅。

新增或修改界面翻译后，先执行目录检查与四种前端构建，再于一般本机开发环境检查变更的画面：

```sh
npm --prefix frontend run i18n:check
npm --prefix frontend run build:suite
npm --prefix frontend run build:work
npm --prefix frontend run build:knowledge
npm --prefix frontend run build:code
```

修改公开文档后，构建三语文档并检查公开链接与跳转页面：

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv run --project backend --no-sync python scripts/check_docs.py
node scripts/build_docs_redirects.mjs
```

需要浏览器检查时，先执行 `npm --prefix docs run preview`，再打开本机预览。检查修改文章的三语页面、语言切换后的对应路径、标题锚点、搜索结果及手机版版面；确认只有公开清单中的文章出现在网站。

## 参与翻译 {#contributing-translations}

繁体中文根目录是目前的文件来源。其他语言使用相同的相对路径，例如 `docs/guide/work.md` 对应 `docs/en/guide/work.md` 与 `docs/zh-CN/guide/work.md`。只有 `docs/.vitepress/public-pages.json` 列出的文章会公开；新增公开文章时，在清单加入不含语言前缀的相对路径，例如 `guide/work.md`，并创建三语对应文件。清单外的文件仍保留在公开源代码 repo，但不会进入网站、搜索或 sitemap；这是发布范围设置，不是访问控制。

- 以繁体中文原文为准，保持功能、限制、数字与安全说明一致。
- 不翻译命令、API 路径、环境变量、代码、JSON 范例、产品名称与稳定的技术识别字。
- 保留同一篇文章的相对连结、标题 anchor、图片路径和代码区块；新增或移动标题时同步检查连结。
- 更新翻译时，对照原文与另外两种语言，避免只更新导览或首页而漏掉操作及契约细节。
- 执行文件建置与 `scripts/check_docs.py`，并在 PR 中列出来源页面与已更新的语言。

翻译尚未完成时，请明确指出缺少的语言版本，不要以另一种语言的原文充当翻译。

## 检查文档正文 {#checking-document-body}

`i18n:check` 会检查 repo 内所有 Markdown 的三语标题、段落、表格与相对章节 ID，包括不公开上线的文件。公开网站构建则只收录明确清单中的页面；中文页面中的未翻译英文正文，以及英文页面中的中文正文会导致检查失败。命令、代码、API 标识符与产品名称不属于翻译范围。清单内所有文章都必须有繁体中文、简体中文与英文版本。

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/check_docs.py
```

文档预览的浏览器检查应涵盖本次变更的三语公开页面，确认可见正文、语言切换、搜索、章节书签及手机版导航。自动检查用于发现漏译，翻译者仍需对照三语内容，确认功能、限制与用词准确。

## 文档站发布 {#documentation-publishing}

正式文档站发布于组织根域名 <https://ordivant-ai.github.io/>，由 `ordivant-ai/ordivant-ai.github.io` 的 GitHub Pages 提供。`ordivant-ai/ordivant` 保存文章源代码；GitHub Actions 依公开清单检查并构建文档。应用服务需单独部署。
