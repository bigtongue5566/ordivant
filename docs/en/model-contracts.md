# Work model connection and Agent configuration

Revision: 2026-10-07. Python Work owns authorization and configuration. Identity credentials and provider credentials are separate. Only the organization administrator configures provider connections; agents and scoped member managers cannot read or change credentials. Model selection does not rotate a provider key.

## Public Work API

- `POST /api/model-settings/discover`: organization admin only; cookies require Origin/CSRF. Body `{id,base_url,api_key?}` fetches OpenAI-compatible `{base_url}/models` and returns `{source:"provider_api",models:[{id,name,context_window?,max_output_tokens?,reasoning_efforts?}]}`. A blank key reuses credentials only for the same organization, provider ID, and Base URL. Missing capabilities stay unknown. Fetching changes neither settings nor revision. Requests have a 15-second timeout, a 1 MiB/2,000-item response limit, no retries or redirects, no upstream error bodies, no idempotency caching, and `Cache-Control:no-store`.

- `GET /api/model-settings`: organization administrator only. Returns `{providers:Provider[], default:ModelSelection|null,revision:number}`. Never returns API keys or ciphertext.
- `PUT /api/model-settings`: organization administrator only, Origin/CSRF protected for cookies. Body `{providers:[{id,name,base_url,api_key?:string,enabled:boolean,models:ModelDefinition[]}],default:ModelSelection|null}`. Omitting or sending an empty `api_key` preserves that provider's existing key. New enabled providers require a key. Replacement retains keys only within the current organization and same provider ID; changing base URL requires an explicitly supplied key. Keys are encrypted at rest with a server-local encryption key under the ignored Work data directory. Credentials never appear in idempotency cache, audit, errors or normal responses. Writes support revision/CAS to prevent lost updates if practical; mutation cannot cache secrets.
- `GET /api/model-catalog`: authorized Work human or scoped agent. Returns `{providers:Provider[],default:ModelSelection|null,revision:number}` for its organization, only enabled/configured providers and with credentials omitted. This supplies the Agent form.
- `Provider`: `{id,name,base_url,enabled,key_configured:boolean,models:ModelDefinition[]}`.
- `ModelDefinition`: `{id,name,context_window:number,max_output_tokens:number,reasoning_efforts:("low"|"medium"|"high"|"xhigh"|"max")[]}`. Limits are operator-provided metadata, not a paid provider verification claim.
- `ModelSelection`: `{provider_id:string,model_id:string,reasoning_effort:"low"|"medium"|"high"|"xhigh"|"max",max_output_tokens:number}`. Validation requires provider/model/effort membership and 16 <= output <= configured model limit; routine run default 4096. Pi's adapter has a minimum of 16; reject smaller selections rather than silently increasing the ceiling. All provider requests enforce `store:false`.
- Agent create/patch add `model_config:ModelSelection|null`. Null means inherit the organization default. Keep the old string `model` field for backward compatibility. Store overrides in a separate table keyed by agent ID so existing business tables need no unsafe ALTER. Agent listings include `model_config` and `effective_model_config`; creation and edit expose the same fields. Explicit null on PATCH really clears the override.
- Dispatch resolves the current effective selection and records a non-secret snapshot in outbox `payload.model_config`. Changes to defaults/Agent settings affect the next dispatch, not an admitted run. Demo without configured provider stays supported and visibly demo; configured live runs must fail instead of falling back to demo.

## Internal runtime handoff

Trusted host operators may import connection settings with the Python-only `import_model_settings(session, organization_id, body)` entry point. It shares API validation, encryption and revision checks, records an operator audit and has no HTTP route. This bootstraps the user-authorized development connection without creating a human account or weakening Identity administrator checks. `scripts/configure_test_model.py` targets only the owned development project and transmits its local key file on Docker exec stdin.

- `POST /api/runtime/outbox/{id}/configuration`: body `{worker_id,delivery_token}`. Only a runtime principal, same organization/project, current unexpired outbox owner and fencing token. Returns `{agent:{id,token},model_config:ModelSelection|null,provider:{id,name,base_url,api_key,models:ModelDefinition[]}|null}` with `Cache-Control:no-store`. This secret-bearing endpoint must bypass the normal idempotency response cache and must not be available to human/agent credentials. Issue a scoped token for exactly the event's assigned agent (hash only in AuthToken; stable on retry and revoke when delivery terminates). The runtime credential itself never performs agent business operations. Do not persist provider/agent secrets in Pi transcripts or run records.
- `POST /api/runtime/outbox/{id}/renew`: same ownership body, renew only valid current lease with the existing fence. Runtime keeps both delivery and task leases alive during a model run.
- Dispatch to a newly created project explicitly admits the same organization's active runtime delivery principal to that project, in the dispatch transaction. It does not grant agent access or cross organizations. Existing scoped outbox enforcement remains.

## Pi runtime

Use the installed real Pi Durable Harness/SQLite and Pi AI Responses provider. Register operator-configured models rather than assuming the package's static OpenAI catalog contains `gpt-6.1-sol`. Fetch the internal handoff before claiming; keep keys in server memory. Apply provider base URL, selected model, supported reasoning effort and output bound; force `store:false`. Respect admitted snapshots on retries and persist only non-secret selections.

Runtime should choose per-event live execution from a configured handoff even when its process-level fallback is demo. Unconfigured events retain documented demo behavior. No failure fallback. Record actual returned model identity from the upstream completion event, token usage and observed tool names/call counts in a safe run receipt; currency remains unknown unless configured/measured independently. `input_tokens` includes `uncached_input_tokens`, `cached_input_tokens` and `cache_write_tokens`, rather than relabeling Pi's uncached input as total input. Unknown usage is null. Automatic model-generation retries and provider redirects are disabled. API health identifies the default/fallback mode, not proof of a live completion. Duplicate request IDs and resume remain idempotent; pending live runs require a fresh authorized handoff after process restart.

## Local acceptance

Use the exact user-authorized HTTPS endpoint/model; do not send credentials elsewhere, auto-select another model or retry indefinitely. External prompts contain only synthetic acceptance data. Check a real Responses completion plus model-issued platform tool calls, task submission into `in_review`, authorized independent reviewer separation and restart receipt persistence. Report requested and returned model IDs, token usage, real tool evidence and limitations. Preserve user's accounts and unrelated tasks. Development and production have independent settings/databases; populate the provided test connection only in development unless a later test explicitly needs the isolated QA instance.
