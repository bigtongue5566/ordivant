# Ordivant Knowledge

Knowledge 用来保存可追溯的规格、决策和背景数据。每个 Space 都有独立成员范围；文档内容采不可变版本，搜索依目前实际保存的标题和正文做文字比对。

## 创建文档与版本 {#create-a-document-and-publish-versions}

1. 由 Identity 管理员创建 Space 及其资源范围，填入唯一 key、名称与说明；Space 创建后，再授权 Knowledge manager、writer 或 reader。
2. 选择 Space，创建文档，填入标题、摘要、正文和标签。初次创建会同时保存文档及 `v1`。
3. 在「来源与 provenance」加入文档采用的 Work、Code 或外部来源。来源是可追溯引用，不代表读者自动取得来源产品的访问权。
4. 修改已存在的文档时，先在最新版本页面的「共同草稿」编辑正文。等草稿显示「已保存」后选择「发布新版本」，填入变更摘要、可选的版本标题和引用，再确认发布。系统创建新版本；旧版本、内容 hash 和引用保持不变。如果草稿已被其他人更新，会提示冲突，请查看合并后的最新内容再发布。

文档读者可用标题、正文文字和标签搜索，打开文档后切换查看任一精确版本。画面会显示版本 URI、创建时间、内容 SHA-256、变更摘要和来源。搜索是持久化文字搜索；本产品不提供矢量索引或 RAG 搜索。

## 多人共同编辑草稿 {#shared-draft-collaboration}

Knowledge Writer 和 Manager 可以在文档最新版本页面编辑共同 Markdown 草稿；Reader 可以查看共同草稿，但不能修改。文档 Space 的授权范围同样适用于 Agent。这项工作不需要 LLM。

1. 打开文档的最新版本。在「共同草稿」区选择「编辑」，撰写或修改正文；需要检查格式时切换「预览」。在线协作者列表显示已登录的共同编辑成员；Agent 通过 REST 或 MCP 更新草稿时，作者会记录在审计事件中。
2. 留意草稿状态：显示**已连接**和**已保存**，表示服务器已确认保存，其他连接会收到合并后的内容。显示**正在重新连接**或**尚有变更待保存**时先不要离开页面；未确认的离线修改只保存在当前浏览器标签页的内存中，关闭或重新加载页面可能会丢失。
3. 其他 Writer／Manager 可以同时编辑，变更会合并到同一草稿。Agent 也可通过 REST 或 MCP 读写这份草稿；不要通过其他 API 直接覆盖整篇正文，以免覆盖其他编辑者的变更。
4. 要留下可引用的正式内容，请等连接恢复且状态显示**已保存**后，选择「发布新版本」，输入变更摘要并确认。只有实时连接且已保存的草稿才能发布。发布会创建不可变版本，旧版本保留在版本历史中。

如果发布时出现版本冲突，先重新加载共同草稿，核对最新版本与合并内容，补上需要的修改并等待显示已保存，再发布。如果权限失效，草稿会变为只读；请联系管理员恢复 Space 授权后再继续。

## 引用特定版本 {#cite-an-exact-version}

文档版本的标准 URI 格式如下：

```text
ordivant://knowledge/spaces/{space_id}/documents/{document_id}/versions/{version}
```

从版本阅读页拷贝完整 URI，引用时保留 `/versions/{version}`，不要只连到可变动的文档首页。可在 Work Task 的输入／证据中记录该 URI，或在 Code 创建 PR 时加入 Knowledge 来源引用。Knowledge 的版本引用不会替其他产品查找或授权数据；读者仍须有该 Space 的权限。

## 记录决策 {#record-decisions}

在「决策纪录」创建标题与内容，可选择关联文档，再附上依据来源。决策纪录保留创建者与引用，适合记录采用的方向、取舍和生效版本；后续改变决策时另建新纪录，避免抹除历史脉络。

## 权限与范围 {#permissions-and-scope}

- **Manager**：管理 Space 与授权范围，可创建文档、发布版本和决策。
- **Writer**：在已授权 Space 创建文档、共同编辑草稿、发布新版本和记录决策。
- **Reader**：阅读共同草稿与历史版本、搜索并拷贝引用；不可编辑或发布。

Identity 管理员授予成员明确 Space 范围。登录 Knowledge 不代表能读取所有 Space；同一个 URI 也不是跨产品权限。管理员与成员管理方式见[管理指南](administration.md)。

## 页面树与范本 {#page-tree-and-templates}

在文档库选择「新建文档」，可从「文档范本」选择内置 PRD、会议记录、架构决策记录（ADR）或标准作业程序（SOP），也可以直接撰写。创建时可指定同一 Space 的「上层文档」；文档列表会以缩进显示层级。Writer／Manager 可在文档阅读器选择「文档结构」调整父文档或封存状态；层级不能跨 Space，也不能形成循环。

封存文档会从默认搜索列表隐藏，勾选「显示已封存」即可再次管理。封存不会删除文档或版本；如果文档仍有子文档，必须先将子文档移到其他父文档，再封存。Space Writer／Manager 也可在新建文档流程选择「创建空间范本」，输入名称、说明和 Markdown 正文；自定义范本仅供该 Space 使用。

## 留言、Markdown 与版本比较 {#comment-format-compare-restore}

在渲染后的文档预览中选择一段文字，再到「文档留言」新增留言，系统会记录引用文字和当时已发布的版本。Reader 可以阅读；Writer／Manager 可留言、直接回复一层，并标记解决或重新打开。留言以纯文本显示。文档更新后，旧版本引用会标记为较旧，不会自动移到新版本。

最新版本的共同草稿提供粗体、斜体、链接、图片 Markdown 和表格工具，以及实时预览；这些控件会在同一份共同草稿中插入 Markdown。图片工具只插入 URL 和替代文字，不会上传图片。Canonical 内容仍是实时协作的 Markdown 草稿，这不是另一份同步内容，也不是完整的 WYSIWYG 区块编辑器。

Writer／Manager 可在文档阅读器选择「比较版本」，挑选两个已发布版本查看差异。选中历史版本后按「还原版本」会以该版本内容创建一个新的不可变版本；旧版本不会被改写。如果当前版本已变化，或共同草稿有尚未发布的协作者修改，还原会遇到冲突并停止。先确认并处理共同草稿，再重试。
